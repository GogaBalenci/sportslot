# СпортСлот

«СпортСлот» помогает жителю, который хочет начать заниматься спортом, быстро найти тренировку рядом с домом или работой и сразу забронировать место из гарантированной квоты партнёрского зала.

Основной сценарий доступен в MAX: пользователь отвечает боту на вопросы о виде спорта, времени и районе; бот показывает до трёх вариантов и позволяет забронировать место. Мини-приложение, подключённое к боту, даёт дополнительный экран для визуального сравнения карточек и бронирования. Если мини-приложение недоступно, путь целиком остаётся доступен в чате.

> Данные площадок, расписание и квоты — синтетические тестовые данные. Квота — не вместимость зала, а число мест, заранее выделенных партнёром сервису.

## Архитектура

```text
MAX чат-бот ──webhook──> Go API ──> PostgreSQL 16
     │                         │
     └──deep link──> MAX mini-app (React + Vite + MAX UI)
                              │
                         REST /api/v1/*
```

- **Go API** — `chi`-роутер, сервисы поиска, бронирования, диалога и напоминаний; PostgreSQL-репозитории на `pgx`.
- **PostgreSQL** — хранит пользователей MAX, площадки, конкретные слоты и брони. При создании брони квота списывается атомарным `UPDATE ... WHERE quota_booked < quota_total` внутри транзакции.
- **MAX bot** — принимает webhook, ведёт диалог и отправляет результат через API MAX. Токен передаётся только окружением.
- **Mini-app** — React + TypeScript + Vite; MAX Bridge подключён официальным CDN и получает `window.WebApp.initDataUnsafe.user.id`. UI использует `@maxhub/max-ui`.
- **NotifierService** — фоновая горутина проверяет ближайшие тренировки и отправляет напоминание примерно за час.

## Быстрый запуск в Docker

Нужны Docker Engine и Docker Compose v2. Скопируйте пример окружения и задайте локальный пароль БД:

```bash
cp .env.example .env
docker compose up --build
```

Команда поднимает PostgreSQL, API и статическую сборку мини-приложения. Миграция применяется API автоматически до seed-загрузки. Повторный запуск безопасен: миграция и seed-данные идемпотентны, данные БД хранятся в volume `postgres-data`.

Откройте:

- мини-приложение: `http://localhost:5173`;
- API: `http://localhost:8080`;
- health-check: `http://localhost:8080/api/v1/health`.

Для подключения мини-приложения к настоящему боту MAX разместите его за HTTPS, укажите публичный адрес в `MINI_APP_URL` и в настройках бота MAX. Для локальной браузерной проверки используется явно тестовый `max-test-user-001`; внутри MAX он заменяется ID из Bridge.

## Окружение, порты и зависимости

| Переменная | Назначение | Значение для локального запуска |
| --- | --- | --- |
| `API_PORT` | внешний порт Go API | `8080` |
| `MINI_APP_PORT` | внешний порт mini-app | `5173` |
| `POSTGRES_PASSWORD` | пароль локальной БД | задаётся в `.env`, не коммитится |
| `VITE_API_BASE_URL` | URL API, доступный браузеру | `http://localhost:8080` |
| `MINI_APP_URL` | URL mini-app для deep link бота | `http://localhost:5173` |
| `MAX_BOT_API_BASE_URL` | базовый URL MAX Bot API | `https://botapi.max.ru` |
| `MAX_BOT_API_TOKEN` | токен, выданный организаторами | пустой локально; не хранить в Git |
| `MAX_WEBHOOK_SECRET` | секрет проверки входящих webhook-запросов | задаётся в `.env`, не коммитится |
| `CORS_ORIGINS` | разрешённые origin мини-приложения через запятую | `http://localhost:5173` |
| `NOTIFIER_INTERVAL_SECONDS` | частота проверки напоминаний | `120` |
| `VITE_DEMO_MAX_USER_ID` | идентификатор только для браузерной демо-проверки | `max-test-user-001` |

API слушает `8080` в контейнере, PostgreSQL — внутренний порт `5432`, Nginx mini-app — `80` в контейнере. Зафиксированные зависимости находятся в `go.mod`/`go.sum` и `web/mini-app/package.json`/`pnpm-lock.yaml`.

Для отдельной разработки mini-app используйте Node.js 20+ и pnpm: `cd web/mini-app && pnpm install --frozen-lockfile && pnpm run build`.

## Данные и внешние интеграции

`seed-data/venues.json` — воспроизводимый набор из четырёх московских площадок и семи будущих слотов. Структура полей опирается на Всероссийский реестр объектов спорта Минспорта России, но сами адреса, расписания и квоты синтетические. При первом старте API загружает файл только в пустую БД.

Внешняя интеграция — MAX Bot API. В MVP формат исходящих сообщений и входящих webhook-обновлений упрощён; перед публикацией необходимо сверить его с текущей документацией MAX и настроить webhook на публичный HTTPS URL `/bot/webhook`. Входящий webhook должен передавать секрет в заголовке `X-Webhook-Secret`, совпадающий с `MAX_WEBHOOK_SECRET`. Bridge загружается с `https://st.max.ru/js/max-web-app.js`; MAX UI распространяется через npm.

## Проверка основного сценария

После `docker compose up --build` выполните следующие команды в новом терминале.

1. Проверьте API:

   ```bash
   curl http://localhost:8080/api/v1/health
   # {"status":"ok"}
   ```

2. Найдите свободные занятия по боксу:

   ```bash
   curl -X POST http://localhost:8080/api/v1/search \
     -H 'Content-Type: application/json' \
     -H 'X-MAX-User-ID: max-test-user-001' \
     -d '{"sport_type":"boxing","lat":55.751244,"lon":37.618423,"radius_km":8}'
   ```

   Возьмите `results[0].slot.slot_id` из ответа. Например, для свежей БД это `b1111111-0000-0000-0000-000000000001`.

3. Создайте бронь:

   ```bash
   curl -X POST http://localhost:8080/api/v1/bookings \
     -H 'Content-Type: application/json' \
     -H 'X-MAX-User-ID: max-test-user-001' \
     -d '{"slot_id":"b1111111-0000-0000-0000-000000000001","source_channel":"miniapp"}'
   ```

   Ожидается `201` с JSON брони. Повторяйте запрос до исчерпания квоты, затем API вернёт `409` и `code: quota_exceeded`.

4. Откройте `http://localhost:5173`, выберите вид спорта и нажмите «Забронировать». Карточка покажет оставшееся количество мест, а успешное действие — понятное подтверждение.

5. Для проверки диалога в MAX настройте в панели бота URL `https://<ваш-домен>/bot/webhook`, передайте заголовок `X-Webhook-Secret` со значением `MAX_WEBHOOK_SECRET`, отправьте `/start`, выберите спорт, ответьте на вопрос о дате любым текстом и затем на вопрос о районе. Бот покажет карточки; кнопка «Сравнить в приложении» открывает указанное `MINI_APP_URL`.

## Ожидаемое поведение и ошибки

- `POST /api/v1/search` возвращает только будущие слоты с доступной квотой.
- `POST /api/v1/bookings` требует `X-MAX-User-ID`; без него ответ — `401`.
- Некорректное тело или обязательный параметр возвращают `400`; неизвестный слот — `404`; занятая квота — `409`.
- Отмена брони (`DELETE /api/v1/bookings/{id}`) возвращает место в квоту. Перенос — `PATCH /api/v1/bookings/{id}/reschedule` с `{"new_slot_id":"..."}`.
- Ошибка одного напоминания не останавливает обработку других задач и сервер.

## Ограничения MVP

- Гарантируется только выделенная сервису квота; реальной интеграции с ERP/CRM залов и оплаты нет.
- Для REST API mini-app передаёт `X-MAX-User-ID`, а сервер дополнительно проверяет владельца брони. Для production также необходима серверная проверка подписи `initData` MAX вместо доверия к `initDataUnsafe`.
- Вебхук и отправка сообщений используют MVP-адаптер и нуждаются в проверке соответствия актуальному контракту MAX перед публикацией.
- Для запуска внутри MAX мини-приложению обязателен HTTPS; `localhost` служит только локальной демонстрации.
- Тестовые даты слотов актуальны для демо-периода; при следующем запуске проекта seed следует обновить.

## Остановка и повторный запуск

```bash
docker compose down
docker compose up --build
```

Первый вариант сохраняет данные в `postgres-data`. Чтобы начать сценарий с чистыми квотами и заново загрузить seed, удалите только volume проекта:

```bash
docker compose down -v
docker compose up --build
```

Не используйте `-v`, если хотите сохранить созданные брони.
