# СпортСлот

СпортСлот помогает жителю Ростова-на-Дону, который давно собирается начать заниматься спортом, за пару минут найти пробную тренировку рядом с домом, записаться прямо в MAX и дойти до первого занятия.

- **Чат-бот:** https://max.ru/t674_hakaton_max_bot — весь путь проходится в чате: подбор, запись, напоминания, перенос и отмена.
- **Мини-приложение** открывается из бота: карта залов, расписание на две недели, QR-пропуск, переписка со студией, абонементы и онлайн-оплата, отзывы.
- **Кабинет студии** — в том же мини-приложении: расписание, записи с карточкой клиента, отметка по QR, сообщения клиентов, абонементы, приём оплаты через ЮKassa или Т-Кассу, статистика и утренняя сводка. Администратор подключается по ссылке-приглашению.
- **API:** https://sportslot.space/api/v1 (спецификация — `openapi/openapi.yaml`, проверки — `openapi/DATA-API.yaml`).

## Какие данные реальные, а какие модельные

| Данные | Источник | Статус |
| :--- | :--- | :--- |
| Каталог залов Ростова: 98 площадок с адресами, часами работы и контактами, если они есть | OpenStreetMap, выгрузка через Overpass API 29.09.2026, лицензия ODbL | **Реальные** |
| Студии с онлайн-записью, расписание, квоты мест, цены пробных занятий | 8 вымышленных демо-партнёров, по одному в каждом районе | **Модельные**, помечены «демо-партнёр» в боте и в приложении |
| Записи, лист ожидания, отметки посещений, оценки | Создаются пользователями в пилоте | Настоящие данные сервиса |

Реальных договоров со студиями у команды нет, поэтому онлайн-запись показана на демо-партнёрах: на них можно пройти весь путь от записи до QR-отметки. По реальным залам из каталога сервис честно показывает контакты и маршрут и не имитирует запись. Демо-партнёров можно отключить переменной `DEMO_DATA=off` — останется только реальный каталог.

## Основной пользовательский сценарий

1. `/start` в боте → выбор вида спорта или подбор «Не знаю, чем заняться» (5 вопросов, у результата есть объяснение).
2. Когда удобно: сегодня, завтра, будни вечером, выходные, любое время.
3. Где: геолокация одной кнопкой (`request_geo_location`), адрес (в боте — текстом, в мини-приложении — с подсказками) или район. В веб-версии MAX на компьютере кнопка геолокации в чате не работает, поэтому рядом есть «Определить через приложение»: мини-приложение берёт геолокацию браузера, сохраняет её, и бот сразу продолжает подбор в чате — дальше можно идти и в чате, и в приложении.
4. Как добираться: пешком, на общественном транспорте или на машине и сколько минут готов тратить (в мини-приложении — ползунок 10–60 минут). Время в пути считается по реальным маршрутам 2ГИС с учётом расписания транспорта. Если в лимит попало меньше четырёх залов, ниже показываются ближайшие «чуть дальше». Ссылка «Маршрут» сразу открывает Яндекс Карты с точкой старта и выбранным способом передвижения.
5. Карточки: сначала студии с онлайн-записью и ближайшими занятиями, затем другие залы. В каждой карточке — время в пути («12 мин на транспорте»), адрес, кнопки времени занятия или контакты и маршрут.
6. Запись в одно касание → подтверждение с кодом входа, списком «что взять», маршрутом и точкой на карте.
7. За 24 часа — напоминание с кнопками «Иду / Не смогу», за 2 часа — адрес и код входа. «Не смогу» отменяет запись, и место сразу уходит первому из листа ожидания.
8. На входе администратор сканирует QR-пропуск в кабинете студии → бот спрашивает «Как прошло?» и предлагает записаться на то же время через неделю.
9. Вопрос студии — кнопка «Написать студии» в подтверждении записи, в карточке студии или в QR-пропуске. Администратор отвечает в кабинете, ответ приходит клиенту в чат.
10. **С другом.** «Пойду с другом» при записи или «+1 место для друга» в подтверждении бронирует второе место. Бот присылает сообщение со ссылкой, которое удобно переслать: друг открывает его и получает свой QR-пропуск и напоминания. Если друг не открыл ссылку за 2 часа до начала, место освобождается для других (или уходит первому из листа ожидания), а пригласившему приходит сообщение.
11. **Несколько недель и абонементы.** На повторяющееся занятие можно записаться сразу на 2–4 недели. Если у студии есть абонементы, их можно купить в карточке студии; визиты списываются при записи и возвращаются при отмене.
12. **Оплата онлайн.** Если студия подключила ЮKassa или Т-Кассу, пробное занятие и абонементы оплачиваются картой или через СБП; деньги идут напрямую студии.
13. **Отзывы.** После «Как прошло?» можно дописать пару слов. Средняя оценка и отзывы видны в карточке студии и в поиске, если студия включила их показ.

Если места закончились, можно встать в лист ожидания: при отмене чужой записи сервис сам записывает первого в очереди и присылает ему сообщение.

## Кабинет студии и подключение студий

Роли:

| Роль | Как получает доступ | Что видит |
| :--- | :--- | :--- |
| Команда СпортСлот | MAX id в `PLATFORM_ADMIN_IDS` (бот показывает свой id по команде `/id`) | Раздел «Платформа»: подключение студий из каталога или по адресу, ссылки-приглашения, отзыв доступа; кабинеты всех студий |
| Администратор студии | Одноразовая ссылка-приглашение `https://max.ru/<бот>?startapp=studio_<токен>`, действует 7 дней | Кабинет только своих студий |
| Демо-доступ для жюри | Код `PARTNER_DEMO_CODE` | Кабинеты демо-студий; профиль и чужие сообщения не меняются |

Что есть в кабинете:

- **Записи** по дням. Нажатие на запись открывает карточку клиента: занятие, код входа, история посещений и неявок в этой студии, переписка, кнопка «Напомнить».
- **Расписание** — недельный шаблон: название, вид спорта, день недели, время, длительность, сколько мест отдаётся новичкам. Сервис сам поддерживает занятия на 14 дней вперёд. У демо-студий шаблон создан из текущего расписания, записи сохранились. Если на занятие уже записались, правка шаблона не двигает его время. Любое ближайшее занятие можно закрыть для записи (замок) или отменить: все записавшиеся получат «Запись отменена администратором студии» с телефоном студии и кнопками «Выбрать другое время» и «Написать студии».
- **Уведомления в бот** администраторам студии: новая запись, отмена, перенос, запись из листа ожидания, «Иду» и «Не смогу» на напоминание. Имя клиента в уведомлении — ссылка на его профиль в MAX, кнопка «Открыть в кабинете» ведёт в карточку клиента.
- **Сообщения.** Клиент пишет студии из бота или мини-приложения, администратор получает уведомление и отвечает в кабинете — ответ приходит клиенту в чат. Номер телефона клиента студии не передаётся.
- **Абонементы.** Студия заводит пакеты занятий (число визитов, срок, цена). Клиент покупает онлайн, если подключена оплата, или оставляет заявку с оплатой на месте — администратор подтверждает её галочкой, и абонемент включается.
- **Оплата.** Данные магазина ЮKassa (shopId и секретный ключ) или Т-Кассы (TerminalKey и пароль), переключатели «Принимать оплату онлайн» и «Пробное занятие — тоже онлайн», список оплат за 30 дней. Подробности — в разделе «Онлайн-оплата».
- **Статистика** за 30 дней: записи, пришли, неявки, отмены заранее, новые и повторные клиенты, средняя оценка, время ответа на сообщения, оплаты онлайн, все отзывы с именами.
- **Профиль** — логотип, короткое описание (показывается под названием студии), контакты и «что взять», переключатели «Показывать оценки и отзывы» и «Утренняя сводка в 9:00». Логотип — PNG, JPG или WebP от 256×256 до 5 МБ: на телефоне он обрезается до квадрата и уменьшается до 512×512, сервер проверяет формат и перекодирует картинку (метаданные и посторонние данные не сохраняются), а отдаёт её с долгим кэшем по адресу с версией.
- **Утренняя сводка** приходит администратору в бот в 9:00: записи на сегодня по времени, сообщения без ответа, заявки на абонементы, оплаты за вчера. Если ничего нет — не приходит.
- **Время ответа.** Если клиент ждёт ответа больше часа, бот напоминает администраторам; через три часа клиенту приходит телефон студии. В статистике — медиана времени первого ответа и доля ответов в течение часа. Ночью (с 21:00 до 9:00) напоминания не отправляются.
- **Как работать** — короткая инструкция и учебный QR-пропуск (код `000 000`): на нём администратор пробует сканер, ничего не меняя в реальных записях.

### План подключения первых 3–5 студий

1. **Отбор (1-я неделя).** Студии из каталога с пробными занятиями и свободными местами в будни: йога, плавание, единоборства, танцы — по одной-две в районе. Критерий — готовность отдать 2–4 места в неделю на пробные занятия.
2. **Подключение (15 минут на студию).** Команда в разделе «Платформа» находит зал в каталоге или добавляет по адресу и создаёт ссылку-приглашение. Администратор открывает её в MAX и сразу попадает в кабинет.
3. **Онбординг (30 минут, на месте или по видео).** Вместе с администратором: вносим недельное расписание и квоты, заполняем телефон и «что взять», тренируемся на учебном QR-пропуске (второй телефон сканирует экран «Как работать»), пробуем ответить на тестовое сообщение. В студии остаётся распечатка «как отметить посетителя».
4. **Первые две недели.** Ежедневно смотрим неявки и время ответа на сообщения, раз в неделю созваниваемся с администратором. Студия видит в статистике, сколько новых клиентов пришло и сколько записалось повторно.
5. **Метрики успеха пилота:** доля пришедших от записавшихся выше 60 %, ответ студии на сообщение в течение часа, хотя бы один повторный визит на студию за две недели.

## Онлайн-оплата

У каждой студии свой магазин в ЮKassa или Т-Кассе, деньги приходят напрямую на её счёт. СпортСлот создаёт платёж и отмечает оплату.

1. Клиент нажимает «Оплатить» (бот или мини-приложение) → API создаёт платёж в магазине студии: ЮKassa `POST /v3/payments` с ключом идемпотентности, Т-Касса `POST /v2/Init` с подписью Token. Клиент оплачивает картой или через СБП на странице платёжной системы.
2. После оплаты платёжная система возвращает клиента ссылкой `https://max.ru/<бот>?startapp=pay_<id>` в мини-приложение, экран показывает статус.
3. Подтверждение приходит тремя путями, и обрабатывается один раз:
   - уведомление ЮKassa на `/api/v1/payments/yookassa/{venue_id}` — оно не подписано, поэтому сервер перепроверяет статус запросом `GET /v3/payments/{id}` с ключом магазина;
   - уведомление Т-Кассы на `/api/v1/payments/tbank/{venue_id}` — проверяется подпись Token паролем терминала, ответ `OK`;
   - фоновая перепроверка неоплаченных платежей раз в минуту в течение двух часов (на случай, если уведомления не настроены).
4. Пробное занятие помечается оплаченным, абонемент включается; клиенту и администраторам приходят сообщения.

Ключи магазинов хранятся в базе зашифрованными (AES-256-GCM, ключ сервера `PAYMENT_SECRET_KEY`), в ответах API их нет — только «сохранён ••3456». Сумма из ответа платёжной системы сверяется с суммой платежа. Для проверки без денег подходят тестовый магазин ЮKassa и тестовый терминал Т-Кассы.

| Что | Ограничение |
| :--- | :--- |
| Бот | Не больше 5 событий за 3 секунды от одного человека; одинаковые команды и нажатия подряд (за 2 секунды) считаются одним. Лишнее отбрасывается, на кнопку приходит «Не так быстро», на текст — одно предупреждение в 30 секунд |
| Запросы мини-приложения и кабинета | Не больше 40 изменяющих запросов в минуту от пользователя; уведомления платёжных систем — 300 в минуту с адреса |
| Записи | Не больше 10 своих будущих записей и 12 новых записей в час |
| Место для друга | Одно к записи, не больше двух непринятых одновременно, не позже чем за 2 часа до начала; непринятое место освобождается за 2 часа до начала |
| Абонементы | Покупка в два шага (условия → подтверждение); повторное нажатие не создаёт заявку и не пишет студии снова; одна открытая заявка в студии, не больше трёх всего и пяти в сутки |
| Сообщения студии | Не больше 5 одной студии за 10 минут и 20 всем студиям за час |

При срабатывании лимита API отвечает `429` с понятным текстом, бот присылает тот же текст.

## Мониторинг и бэкапы

В прод-режиме работает отдельный сервис `ops` (`cmd/ops`, образ на основе `postgres:16-alpine`, где есть `pg_dump`):

- раз в минуту проверяет `http://api:8080/api/v1/health` внутри сети и `https://<домен>/api/v1/health` снаружи. `health` отвечает «ok», только если API видит базу. После трёх неудач подряд администраторам платформы (`PLATFORM_ADMIN_IDS`) приходит сообщение в MAX, после восстановления — сообщение с длительностью простоя;
- каждый день в `BACKUP_HOUR` (по умолчанию 04:00 МСК) делает `pg_dump` в `./backups/sportslot-ГГГГ-ММ-ДД.dump`, хранит `BACKUP_KEEP_DAYS` дней (не меньше трёх последних копий), при ошибке присылает предупреждение;
- предупреждает, если на диске осталось меньше 1 ГБ.

Команда `/status` в боте (только для администраторов платформы) показывает, сколько работает API, отвечает ли база, когда был последний бэкап и последняя проверка мониторинга.

Восстановление из копии:

```bash
docker compose -f compose.yaml -f compose.prod.yaml exec -T db \
  pg_restore -U sportslot -d sportslot --clean --if-exists < backups/sportslot-2026-10-23.dump
```

Сервис `ops` работает на том же сервере, поэтому если сервер выключится целиком, он не напишет. Для этого случая достаточно бесплатной внешней проверки (например, «Яндекс Мониторинг» или UptimeRobot) на `https://<домен>/api/v1/health`.

Ключевые технические решения:
- **Запись.** Место списывается из квоты в транзакции с `SELECT … FOR UPDATE` строки занятия. Частичный уникальный индекс не даёт записаться на одно занятие дважды. Повторное нажатие «Записаться» возвращает существующую запись. Тест: 8 одновременных запросов на последнее место → ровно одна запись.
- **Отмена.** В той же транзакции отмены освободившееся место уходит первому из листа ожидания.
- **Состояние диалога** хранится в PostgreSQL: перезапуск API не сбрасывает сценарий.
- **Авторизация мини-приложения** — только по подписанным данным запуска MAX (`Authorization: tma <initData>`), срок жизни подписи — час. Заголовок `X-MAX-User-ID` принимается только для тестовых учётных записей из `TEST_MAX_USER_IDS` и в режиме `APP_ENV=dev`.
- **Сообщения бота** оформлены HTML-разметкой MAX (`format: "html"`): жирные заголовки, курсив, цитата «что взять», строки с иконками. Всё, что приходит из данных (названия, адреса), экранируется. Телефоны приводятся к виду «+7 863 …», часы работы из OpenStreetMap склеиваются: «пн–сб 11:00–22:00».
- **Геолокация.** В MAX Bridge нет метода геолокации, а WebView на телефоне не всегда отдаёт её браузерным API. Поэтому последняя точка, отправленная боту (кнопкой или адресом), хранится в `user_locations`, и мини-приложение берёт её, если своя геолокация недоступна. В веб-версии MAX кнопка геолокации в чате не работает — наоборот, работает браузерная геолокация мини-приложения: кнопка «Определить через приложение» открывает экран, который отправляет точку в `POST /me/location`, а бот продолжает сценарий с того же шага.
- **Время в пути.** Один поиск — до двух запросов к матрице 2ГИС: точка пользователя и до 48 ближайших залов (синхронный режим принимает до 25 точек, запросы идут пачками по 24). Заведомо далёкие залы отсекаются по прямому расстоянию ещё до запроса, ответы кэшируются (пешком — сутки, транспорт и авто — 15 минут), точка пользователя округляется до ~200 м. Если ключа нет, лимит исчерпан или 2ГИС не ответил, время оценивается по расстоянию и помечается «≈» — поиск не ломается. Ключ хранится только на сервере и не попадает в логи.
- **Расписание студий** хранится шаблонами (`schedule_templates`) и разворачивается в занятия на 14 дней при старте и каждые 6 часов. Id занятия стабилен (площадка, название, время), поэтому повторное разворачивание не создаёт дублей. Правка шаблона удаляет только будущие занятия без записей и без листа ожидания.
- **Сообщения webhook** одного пользователя обрабатываются по очереди, разные пользователи — параллельно: быстрые нажатия не перепутываются.
- **Уведомления** отправляет горутина с тикером, без внешних очередей. Флаг «отправлено» ставится до отправки, поэтому одно сообщение не уходит дважды.

## Быстрый запуск в Docker

Одна команда поднимает PostgreSQL, API и мини-приложение:

```bash
docker compose up --build
```

`.env` для локального запуска не обязателен: у всех переменных есть значения по умолчанию. Чтобы включить бота или кабинет студии, скопируйте `cp .env.example .env` и заполните `MAX_BOT_API_TOKEN` и `PARTNER_DEMO_CODE`.

После старта:
- API — http://localhost:8080/api/v1/health;
- мини-приложение — http://localhost:5173. Локально оно работает от тестового пользователя `max-test-user-001` (`APP_ENV=dev`), без MAX.

При старте API применяет миграции, загружает каталог из `seed-data/rostov_catalog.json`, создаёт демо-партнёров и расписание на две недели вперёд. Расписание продлевается автоматически каждые 6 часов, поэтому демо не устаревает.

## Работа с данными

- **Каталог.** `tools/fetch_rostov_osm.sh` выгружает спортобъекты в прямоугольнике Ростова. `go run ./cmd/import-osm -in rostov_osm.json` отбрасывает объекты без названия, закрытые, из Батайска и Аксая, дубли и не относящиеся к тренировкам. Вид спорта определяется по тегам и названию, район — по ближайшему центру района. Итог: 98 площадок. При старте API каталог загружается идемпотентно: площадки обновляются по `external_id`, исчезнувшие из выгрузки удаляются.
- **Демо-партнёры** описаны в `internal/seed/demo.go`: 8 студий, адреса условные. Часть мест в занятиях детерминированно занята «другими клиентами студии», некоторые занятия заполнены полностью — на них виден лист ожидания.
- **Схема БД** — миграции `migrations/*.up.sql`, встроены в бинарник и учитываются в `schema_migrations`. Миграция 002 удаляет московские тестовые данные первой версии.
- **Персональные данные:** хранятся id пользователя MAX и имя из профиля. Телефон не запрашивается. События воронки в таблице `events` содержат только id MAX и технические параметры; `GET /api/v1/stats` отдаёт только агрегаты.

## Тестовые данные и учётные записи

| Что | Значение |
| :--- | :--- |
| Тестовый пользователь (роль `user`) | заголовок `X-MAX-User-ID: max-test-user-001`, внутренний id `c1111111-0000-0000-0000-000000000001` |
| Кабинет студии (роль `partner`) | код из `PARTNER_DEMO_CODE`; для жюри указан на первом слайде презентации. Открывает демо-студии |
| Администратор студии | ссылка-приглашение из раздела «Платформа»; в API — подпись MAX, как у пользователя |
| Учебный QR-пропуск | `SPORTSLOT:000000`, код `000000` — отвечает «учебный пропуск», записи не меняет |
| Флагманский демо-партнёр | площадка `a1111111-0000-0000-0000-000000000001` — «Спортцентр «Прибой»», есть бассейн |
| Служебные занятия для проверок API | `b1111111-0000-0000-0000-000000000001` и `…0002` — всегда в будущем |
| Каталог | `seed-data/rostov_catalog.json` |

## Пошаговый сценарий проверки

### В MAX

1. Откройте https://max.ru/t674_hakaton_max_bot → «Начать».
2. «Не знаю, чем заняться» → ответьте на 5 вопросов → «Искать: …».
3. «Будни вечером» → «Отправить геолокацию» или район → «На транспорте · до 20 мин» → карточки с временем в пути.
4. Нажмите время в карточке демо-партнёра → придёт подтверждение с кодом входа и точкой на карте.
5. «QR-пропуск» → откроется мини-приложение с QR-кодом.
6. Для отметки: в мини-приложении «Мои занятия» → «Я администратор студии» → код с первого слайда → «Сканировать QR-пропуск» (с другого телефона) или введите 6 цифр → в чат придёт «Как прошло?».
7. В кабинете студии у записи есть кнопка «Напомнить»: она сразу присылает напоминание с «Иду / Не смогу», чтобы не ждать сутки.
8. Вкладка «Расписание»: добавьте занятие или закройте запись замком — в поиске оно пропадёт. «Отменить занятие» — записавшиеся получат сообщение об отмене с телефоном студии.
9. В подтверждении записи «Написать студии» → напишите вопрос → во вкладке «Сообщения» кабинета ответьте — ответ придёт в чат.
10. В веб-версии MAX на компьютере: на шаге «Где» нажмите «Определить через приложение» → разрешите геолокацию → бот продолжит подбор.
11. В подтверждении записи «+1 место для друга» → бот пришлёт сообщение со ссылкой, перешлите его второму аккаунту → у него свой QR.
12. Кабинет → «Абонементы» → добавьте абонемент → в карточке студии он появится с ценой; без подключённой оплаты покупка создаёт заявку, её подтверждают галочкой.
13. Кабинет → «Оплата»: данные тестового магазина ЮKassa, «Проверить ключи», включить оплату → «Оплатить онлайн» в подтверждении записи откроет тестовую страницу оплаты.
14. После отметки по QR оцените занятие и напишите пару слов → кабинет → «Профиль» → «Показывать оценки и отзывы» → оценка появится в карточке и поиске.

### Через API (curl)

```bash
B=http://localhost:8080/api/v1
U='X-MAX-User-ID: max-test-user-001'

curl -s $B/health                                   # {"status":"ok"}
curl -s "$B/venues?sport=boxing&district=sovetsky&when=weekday_eve" | head -c 600
# Залы в пределах 20 минут на транспорте от точки (поле travel в каждой карточке)
curl -s "$B/venues?sport=boxing&lat=47.2336&lon=39.6179&mode=transit&max_minutes=20" | head -c 600
# Адрес → координаты (геокодер 2ГИС на сервере)
curl -s "$B/geocode?q=Большая%20Садовая%2C%201"
curl -s -X POST $B/quiz/recommend -H 'Content-Type: application/json' \
  -d '{"answers":{"goal":"stress","water":"love","format":"solo","pace":"calm","contact":"no"}}'

# Запись: 201 — новая, 200 — вы уже записаны (ответ содержит checkin_code)
curl -s -X POST $B/bookings -H "$U" -H 'Content-Type: application/json' \
  -d '{"slot_id":"b1111111-0000-0000-0000-000000000001","source_channel":"miniapp"}'

BOOKING=<id из ответа>
curl -s -X PATCH $B/bookings/$BOOKING/reschedule -H "$U" -H 'Content-Type: application/json' \
  -d '{"new_slot_id":"b1111111-0000-0000-0000-000000000002"}'   # код входа сохраняется

# Кабинет студии: вход, список, отметка по коду
TOKEN=$(curl -s -X POST $B/partner/login -H 'Content-Type: application/json' \
  -d "{\"code\":\"$PARTNER_DEMO_CODE\"}" | sed 's/.*"token":"\([^"]*\)".*/\1/')
curl -s $B/partner/bookings -H "Authorization: Partner $TOKEN"
curl -s -X POST $B/partner/checkin -H "Authorization: Partner $TOKEN" \
  -H 'Content-Type: application/json' -d '{"code":"<6 цифр из записи>"}'   # status: attended

# Тот же токен открывает кабинет демо-студий
P="Authorization: Partner $TOKEN"
curl -s $B/studio/me -H "$P"                                            # студии и счётчики
curl -s $B/studio/a1111111-0000-0000-0000-000000000001/templates -H "$P"   # недельный шаблон
curl -s $B/studio/a1111111-0000-0000-0000-000000000001/stats -H "$P"
curl -s -X POST $B/studio/checkin -H "$P" -H 'Content-Type: application/json' \
  -d '{"code":"000000"}'                                                # учебный пропуск

curl -s -X DELETE $B/bookings/$BOOKING -H "$U" -w '%{http_code}\n'       # 204 или 409, если уже отмечено
curl -s $B/stats                                                          # агрегированная воронка
```

### Примеры ожидаемого поведения

| Действие | Ответ |
| :--- | :--- |
| Запись на занятие без мест | `409 {"code":"quota_exceeded"}`; в боте предлагается лист ожидания |
| Повторная запись на то же занятие | `200` и та же запись с тем же кодом |
| Отмена, когда есть очередь | `204`, первый в очереди получает запись и сообщение в чате |
| Отметка тем же кодом повторно | `409 {"code":"already_checked_in"}` |
| Запрос мини-приложения с поддельной подписью | `401` |
| `X-MAX-User-ID` не тестового пользователя в проде | `401` |
| Несуществующий или некорректный id | `404` |
| Поиск с `DEMO_DATA=off` | только площадки OpenStreetMap |
| Поиск с `mode` и `max_minutes` | только залы в пределах лимита, у каждого `travel.minutes`; при недоступности 2ГИС — `travel.estimated: true` |
| Неизвестный `mode` | `400 {"code":"invalid_mode"}` |
| В лимит попало меньше 4 залов | добавляются ближайшие за лимитом с `beyond_limit: true` |
| `GET /geocode` с несуществующим адресом | `404 {"code":"address_not_found"}`; без ключа 2ГИС — `503` |

## Известные ограничения

- Студии с онлайн-записью — демо-партнёры с модельным расписанием. Для реальной студии нужен договор о квоте мест и выгрузка расписания (API CRM студии или ручной ввод в кабинете).
- Каталог OSM неполный: у части площадок нет адреса или телефона. Данные актуальны на дату выгрузки, обновление — повторный запуск импорта.
- Реальные студии подключаются вручную командой (приглашение по ссылке), договор и квота мест согласуются вне сервиса. Импорта расписания из CRM студий пока нет — расписание вводится в кабинете.
- Клиент и студия переписываются через бота: в мини-приложении сообщения обновляются раз в 10–15 секунд, без push внутри приложения.
- Чеки 54-ФЗ при онлайн-оплате не формируются сервисом: студия использует чеки своей платёжной системы или онлайн-кассу. Возврат денег делается в личном кабинете ЮKassa или Т-Бизнеса; автоплатежей за абонементы нет.
- Импорта расписания из CRM студий (YCLIENTS, Mobifitness, 1С:Фитнес клуб) пока нет — расписание вводится в кабинете.
- Центры районов приблизительные: при поиске по району время в пути не считается, сортировка — по расстоянию. Точное время — от геолокации или адреса.
- Ключ 2ГИС в пилоте пробный (на месяц). После его окончания поиск продолжит работать на оценке по расстоянию; для продакшена нужен платный тариф (оплата за пары точек).
- Карта в мини-приложении требует ключ Яндекс Карт; без ключа показывается запасная карта с подложкой OpenStreetMap.
- Оплата пробных занятий не реализована: цена показывается, оплачивается на месте.

## Деплой на сервер

MAX доставляет webhook только по HTTPS на порт 443 с доверенным сертификатом. `compose.prod.yaml` добавляет Caddy, который получает сертификат Let's Encrypt и раздаёт с одного домена API (`/api/*`, `/bot/webhook`) и мини-приложение (`/`).

```bash
git clone https://github.com/GogaBalenci/sportslot && cd sportslot
cp deploy/env.prod.example .env   # DOMAIN, POSTGRES_PASSWORD, MAX_WEBHOOK_SECRET, MAX_BOT_API_TOKEN, PARTNER_DEMO_CODE,
                                  # PLATFORM_ADMIN_IDS, PAYMENT_SECRET_KEY (openssl rand -hex 32)
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
docker compose -f compose.yaml -f compose.prod.yaml logs -f api
```

На сервере с 1 ГБ памяти образы надёжнее собирать по одному: `build api`, `build mini-app`, `build ops`, затем `up -d`. Резервные копии базы появляются в `./backups` рядом с проектом.

При старте API проверяет токен (`GET /me`), задаёт команды `/start`, `/my`, `/help` и подписывает webhook `https://$DOMAIN/bot/webhook`. Ручное управление подпиской: `./deploy/max-webhook.sh me | list | subscribe`.

Мини-приложение привязано к боту организаторами, поэтому в проде `MINI_APP_BUTTON=open_app`: кнопки открывают его внутри MAX и передают `start_param` (`venue_…`, `ticket_…`, `sport_…`, `friend_…`, `pay_…`, `studio_…`). Если MAX отклонит кнопку `open_app`, сообщение уйдёт без неё — сценарий целиком проходится в чате.

Интеграция с MAX Bot API сверена с dev.max.ru/docs-api:
- базовый адрес `https://platform-api2.max.ru`, авторизация заголовком `Authorization: <token>`;
- `POST /messages?user_id=…` с `inline_keyboard` (callback, link, open_app, request_geo_location) и вложением `location`;
- `POST /answers`, секрет в `X-Max-Bot-Api-Secret`, события `bot_started`, `message_created`, `message_callback`.

Образ API содержит корневой сертификат НУЦ Минцифры, которого требует `platform-api2.max.ru`.

## Остановка и перезапуск

```bash
docker compose down            # остановка, данные БД сохраняются в томе
docker compose up -d           # повторный запуск
docker compose down -v         # полный сброс БД
docker compose up --build -d   # чистый старт: миграции, каталог и демо-данные создадутся заново
```

Для прод-режима добавьте `-f compose.yaml -f compose.prod.yaml` к каждой команде.
