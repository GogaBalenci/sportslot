# СпортСлот

«СпортСлот» помогает жителю, который хочет начать заниматься спортом, быстро найти тренировку рядом с домом или работой и сразу забронировать место из гарантированной квоты партнёрского зала.

Основной сценарий доступен в MAX: пользователь отвечает боту на вопросы о виде спорта, времени и районе; бот показывает до трёх вариантов и позволяет забронировать место. Мини-приложение, подключённое к боту, даёт дополнительный экран для визуального сравнения карточек и бронирования. Если мини-приложение недоступно, путь целиком остаётся доступен в чате.

> Данные площадок, расписание и квоты — синтетические тестовые данные. Квота — не вместимость зала, а число мест, заранее выделенных партнёром сервису.

## Пользовательский путь: As Is vs To Be

### Текущий процесс (As Is)

| Этап | Что делает пользователь | Что использует | Где боль |
| :--- | :--- | :--- | :--- |
| **1. Поиск** | Ищет секции в поиске/картах/соцсетях | Поисковики, карты, соцсети | 3–5 разных источников, нет единого фильтра по времени |
| **2. Анализ** | Открывает 4–6 сайтов/страниц залов | Сайты залов, группы ВК | Информация неактуальна или отсутствует расписание |
| **3. Сверка** | Сверяет расписание вручную со свободными вечерами | Календарь, блокнот | Ручное сопоставление, нет фильтра «покажи только подходящее время» |
| **4. Уточнение** | Звонит/пишет администратору, чтобы узнать про места | Телефон, мессенджер зала | Долгий ответ (часы/дни) или отсутствие ответа |
| **5. Решение** | Принимает решение или откладывает | — | Из-за задержки мотивация падает, решение откладывается на 1–3 недели |

### Процесс с продуктом «СпортСлот» (To Be)

| Этап | Что происходит | Канал | Результат |
| :--- | :--- | :--- | :--- |
| **1–2. Параметры** | Сбор параметров (вид спорта, время, район) за 3 шага | Чат-бот MAX | Нет ручного поиска по сайтам |
| **3. Подбор** | `matching-service` находит 2–3 подходящих варианта в пределах квоты | Backend Go | Учитывается реальная доступность мест |
| **4. Сравнение** | Вывод вариантов карточками прямо в чате (основной/fallback) | Чат-бот MAX | Сценарий доступен без внешних переходов |
| **4a. Визуал** | Опциональный переход по deep link для сравнения карточек | MAX Mini-App | Наглядный выбор с остатком мест |
| **5. Бронь** | Мгновенное бронирование в один клик из чата или mini-app | Чат / Mini-App | Атомарное резервирование гарантированного места |
| **6. Подтверждение**| Бот мгновенно отправляет подтверждение брони | Чат-бот MAX | Исключены звонки и ожидание ответа |
| **7. Напоминание** | Фоновый воркер присылает напоминание за 1 час до начала | NotifierService | Снижение неявок на первое занятие |

**Измеримый эффект:** время от старта диалога до подтверждённой брони сокращается с 40–60 минут (ручной поиск) до **≤ 3 минут**; число действий пользователя снижается с 5–7 до **≤ 4 шагов**.

## Архитектура

```text
MAX чат-бот ──webhook──> Go API ──> PostgreSQL 16
     │                         │
     └──deep link──> MAX mini-app (React + Vite + MAX UI)
                              │
                         REST /api/v1/*
```

- **Go API** — `chi`-роутер, сервисы поиска, бронирования, диалога и напоминаний; PostgreSQL-репозитории на `pgx/v5`.
- **PostgreSQL 16** — хранит пользователей MAX, площадки, конкретные слоты и брони. При создании брони квота списывается атомарным `UPDATE ... WHERE quota_booked < quota_total` внутри транзакции. Перенос слота защищён от дедлоков детерминированной блокировкой строк `ORDER BY id FOR UPDATE`.
- **MAX Bot Webhook** — принимает webhook, ведёт диалог через `DialogService` и отправляет ответы через MAX Bot API.
- **Mini-App** — React 18 + TypeScript + Vite + `@maxhub/max-ui`. Поддерживает deep link параметры (`?sport=...&user=...`), считывает `initData` через MAX Bridge и корректно отображает статусы квот (включая 409 Quota Exceeded).
- **NotifierService** — фоновая горутина с `time.Ticker`, проверяющая предстоящие тренировки за 1 час. Оснащена Graceful Shutdown через `sync.WaitGroup`.
- **OpenAPI & DATA-API** — спецификации контракта API (`openapi/openapi.yaml`) и конфигурация автоматической проверки жюри (`openapi/DATA-API.yaml`).

## Быстрый запуск в Docker

Все компоненты решения (PostgreSQL, Go API, React Mini-App в Nginx) поднимаются **одной командой**:

```bash
docker compose up --build -d
```

Все переменные окружения имеют безопасные значения по умолчанию для локального тестирования. При необходимости переопределить переменные скопируйте `.env.example`:

```bash
cp .env.example .env
docker compose up --build -d
```

Миграции базы данных применяются автоматически до загрузки seed-данных. Повторный запуск безопасен: миграции и seed-данные идемпотентны, данные БД сохраняются в томе `postgres-data`.

Откройте в браузере:
- **Мини-приложение:** `http://localhost:5173`
- **Go API Health-check:** `http://localhost:8080/api/v1/health`
- **Спецификация OpenAPI:** `openapi/openapi.yaml`
- **Спецификация DATA-API:** `openapi/DATA-API.yaml`

| `MAX_BOT_API_BASE_URL` | базовый URL MAX Bot API | `https://botapi.max.ru` |

## Данные и внешние интеграции

`seed-data/venues.json` — воспроизводимый набор из четырёх московских площадок (бокс, йога, футбол) со слотами, охватывающими период с конца сентября по ноябрь 2026 года. Структура полей опирается на Всероссийский реестр объектов спорта Минспорта России. При первом старте API загружает файл только в пустую БД.

Внешняя интеграция — MAX Bot API. Входящий вебхук проверяет заголовок `X-Webhook-Secret`. Bridge загружается с `https://st.max.ru/js/max-web-app.js`.

## Пошаговый сценарий проверки (curl)

После запуска `docker compose up --build -d` выполните команды:

### 1. Проверка работоспособности (Health-check)
```bash
curl -s http://localhost:8080/api/v1/health
# Ожидаемый ответ: {"status":"ok"}
```

### 2. Поиск свободных слотов по боксу (в радиусе 15 км от центра Москвы)
```bash
curl -s -X POST http://localhost:8080/api/v1/search \
  -H 'Content-Type: application/json' \
  -H 'X-MAX-User-ID: max-test-user-001' \
  -d '{"sport_type":"boxing","lat":55.751244,"lon":37.618423,"radius_km":15}'
```
В ответе возвращаются площадки («Атлант» и «Феникс») с доступными слотами.

### 3. Создание бронирования
```bash
curl -s -X POST http://localhost:8080/api/v1/bookings \
  -H 'Content-Type: application/json' \
  -H 'X-MAX-User-ID: max-test-user-001' \
  -d '{"slot_id":"b1111111-0000-0000-0000-000000000001","source_channel":"miniapp"}'
```
Ожидается статус `201 Created` с JSON созданной брони:
```json
{
  "id": "<BOOKING_ID>",
  "user_id": "...",
  "slot_id": "b1111111-0000-0000-0000-000000000001",
  "status": "confirmed",
  "source_channel": "miniapp"
}
```
*При повторении запроса до исчерпания квоты сервер вернёт `409 Conflict` с кодом `quota_exceeded`.*

### 4. Перенос бронирования на другой слот (Reschedule)
Возьмите полученный `<BOOKING_ID>` и перенесите запись на слот `b1111111-0000-0000-0000-000000000002`:
```bash
curl -s -X PATCH http://localhost:8080/api/v1/bookings/<BOOKING_ID>/reschedule \
  -H 'Content-Type: application/json' \
  -H 'X-MAX-User-ID: max-test-user-001' \
  -d '{"new_slot_id":"b1111111-0000-0000-0000-000000000002"}'
```
Ожидается статус `200 OK` с обновлённым полем `slot_id`. Квота старого слота освобождается, квота нового списывается.

### 5. Отмена бронирования (Cancel)
```bash
curl -s -i -X DELETE http://localhost:8080/api/v1/bookings/<BOOKING_ID> \
  -H 'X-MAX-User-ID: max-test-user-001'
```
Ожидается статус `204 No Content`. Место возвращается в свободную квоту слота.

### 6. Проверка через Mini-App
1. Откройте `http://localhost:5173/?sport=boxing&user=max-test-user-001`.
2. Вид спорта («Бокс») автоматически активируется из query-параметра.
3. Нажмите «Забронировать» — счётчик оставшихся мест уменьшится на 1, отобразится уведомление об успешной записи.
4. При попытке забронировать заполненный слот отобразится понятное сообщение об ошибке (с красным индикатором).

## Спецификации собственного API (для регламента хакатона)

Решение содержит формальные спецификации в папке `openapi/`:
- **`openapi/openapi.yaml`** — спецификация OpenAPI 3.0.3, описывающая все эндпоинты (`/search`, `/venues/{id}`, `/bookings`, `/reschedule`, `/health`), схемы запросов/ответов и коды ошибок.
- **`openapi/DATA-API.yaml`** — файл по регламенту хакатона (9 обязательных пунктов), используемый автоматизированной платформой оценки для валидации сценариев.
